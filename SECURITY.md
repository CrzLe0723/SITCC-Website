# SITCC Security Policy

## About This Policy

The St. Ignatius Coding Club (SITCC) takes the security of its websites, repositories, projects, and other official technology seriously.

This document explains how to report a security issue affecting SITCC technology.

## Supported Projects

This policy applies to official SITCC technology, including:

- Official SITCC websites
- Official SITCC GitHub repositories
- SITCC-developed software and projects
- SITCC-managed accounts and services
- Other technology officially managed by SITCC

## Reporting a Security Issue

If you discover a potential security vulnerability in an official SITCC project, please do not publicly disclose the details before SITCC has had an opportunity to review it.

Instead, report the issue privately to SITCC leadership.

### What to Include

When possible, include:

- A description of the issue
- Which website, repository, or project is affected
- Steps to reproduce the issue
- Screenshots or other relevant evidence
- The potential impact of the issue
- Any other information that could help us investigate

You do not need to be certain that something is a security vulnerability before reporting it.

## What Counts as a Security Issue?

Examples include:

- Exposing private information
- Accidentally publishing credentials or secrets
- Unauthorized access to SITCC accounts or systems
- Security weaknesses in the SITCC website
- Vulnerabilities that could allow someone to modify or delete data
- Malicious code or dependencies affecting an official project
- Improper access to private repositories or resources

This list is not exhaustive.

## Responsible Disclosure

Please do not:

- Attempt to access someone else's account
- Guess or obtain passwords
- Steal, download, or expose private information
- Delete, modify, or damage data
- Disrupt SITCC services
- Use a vulnerability to harm another person
- Publicly disclose an unreported vulnerability before SITCC has had a chance to respond

Testing should be limited to systems and accounts you are authorized to test.

## Response

SITCC leadership will make a reasonable effort to review security reports and determine an appropriate response.

Because SITCC is a student organization, serious security issues may be escalated to the appropriate teacher, school administrator, parent/guardian, service provider, or other responsible authority.

SITCC cannot guarantee a specific response time or that every report will result in a security change.

## Accidental Exposure of Secrets

If you accidentally publish a password, API key, token, or other secret:

1. Do not repost or share the secret.
2. Report it privately to SITCC leadership.
3. If possible, identify where it was exposed.
4. SITCC leadership should work with the appropriate account owner or service provider to revoke or rotate the exposed credential.

Never include an active password, API key, or other secret in a security report.

## Scope

This policy applies only to technology officially managed or operated by SITCC.

It does not authorize testing of third-party services, school systems, personal accounts, or other systems that you do not have permission to test.

For issues involving school systems or school accounts, follow the school's appropriate reporting process.

## Contact

For security concerns, contact SITCC leadership through the official SITCC contact method.

**Do not use public GitHub issues to report security vulnerabilities.**
